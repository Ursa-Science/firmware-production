# URSA CANopen Slave Modules — Firmware

Firmware for the URSA CANopen slave modules: **valve**, **pump**, and **pH/temp**. All three run on the same MCU (STM32G431KBT6) and share one CMake build and one copy of the CANopen stack, so a fix in shared code reaches every device.

## Devices

| Device | Product Code (`0x1018sub2`) | Function | CAN validated |
|--------|:---:|----------|:---:|
| `valve`  | 5 | Solenoid valve actuation | ✅ |
| `pump`   | 3 | Dosing pump (TMC2209 stepper) | ⬜ builds, not yet |
| `phtemp` | 4 | pH + temperature sensing | ✅ |

- **MCU:** STM32G431KBT6 (Cortex-M4F, 128 KB flash / 32 KB RAM)
- **Bus:** CANopen (MicroCANopen Plus stack, CiA 401); bitrate is configurable per device (see [Per-device configuration](#per-device-configuration))

## Repository layout

```
cmake/      Toolchain file, shared MCU flags, add_ursa_device() helper, linker script
vendor/     STM32 HAL 1.2.6 + CMSIS — one copy, shared by all devices
shared/     mco/ (CANopen stack), startup/ — code identical across devices
devices/    valve/ pump/ phtemp/ — each: Core/, MCO_Target/, MCO_CiA401__User/
```

Shared and vendored sources are compiled **into each device** (each supplies its own `stm32g4xx_hal_conf.h` / `mcohw_cfg.h` / node config), not built as a shared library.

## Prerequisites

- **CMake ≥ 3.22** and **Ninja**
- **arm-none-eabi GCC 14.3.1** — the toolchain is *pinned*; configure fails on any other version. It ships with STM32CubeIDE. Override its location with `-DTOOLCHAIN_BIN=<path>` if needed.
- **st-flash** (`brew install stlink`) or STM32CubeProgrammer for flashing

## Build

```bash
# All three devices
cmake --preset default
cmake --build --preset default

# A single device
cmake --build --preset valve
```

Artifacts land in `build/<device>.{elf,bin,hex,map}`.

## Flash

Over ST-LINK (V3), e.g. valve:

```bash
st-flash --connect-under-reset --reset write build/valve.bin 0x08000000
```

> **`--connect-under-reset` matters:** the firmware runs an independent watchdog (IWDG). Without holding the target in reset during the write, the watchdog can reset the MCU mid-flash. This requires the **NRST** line wired between the ST-LINK and the board.

## Per-device configuration

Most device differences are *bindings*, not stack changes, and live in the per-device tiers:

- **CAN bitrate / node ID** — `devices/<dev>/Core/Inc/main.h`, `MCO_CiA401__User/`
- **Peripheral mapping** (e.g. timer, sensor pins) — `devices/<dev>/MCO_Target/`, `Core/`
- **Object dictionary / EDS** — `devices/<dev>/MCO_CiA401__User/EDS/` (generated by CANopen Architect on Windows; see BUILD_NOTES.md)

Editing `shared/mco/` or `vendor/` changes **all three devices** and requires re-validating all three.

## Adding a device

Create `devices/<name>/` with `Core/`, `MCO_Target/`, `MCO_CiA401__User/`, then add one `add_ursa_device(<name>)` line to `CMakeLists.txt` and a preset to `CMakePresets.json`.
